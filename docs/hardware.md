# Профиль железа и результаты benchmark

## 1. Профиль оборудования

Домашняя работа выполнена на следующей конфигурации:

* ОС: Windows
* GPU: AMD Radeon(TM) Graphics (496 МБ)
* CPU: AMD Ryzen 7 5700U with Radeon Graphics
* RAM: 16 ГБ
* Python: 3.12+
* PyTorch: 2.14.0
* Transformers: 5.16.1

Для запуска выбрана модель:

`Qwen/Qwen3-0.6B`

Название модели хранится только в `params.yaml` и не задаётся непосредственно в исходном коде.

## 2. Результаты замеров

Замеры выполнены командой:

```bash
make bench
```

Перед основными измерениями выполняется один прогрев. Время прогрева в итоговую скорость генерации не входит.

Получены следующие результаты:

```text
Модель: Qwen/Qwen3-0.6B

Время загрузки модели: 0.00 сек.
Скорость генерации: 12.15 tokens/sec
Отдельные замеры: 12.15, 12.33, 11.6 tokens/sec
Пиковое потребление RSS: 1864.3 MB
```

Для итогового значения `tokens/sec` используется медиана отдельных измерений. Это позволяет уменьшить влияние единичного выброса при измерении.

Замер времени загрузки и скорости генерации выполняется отдельно, поскольку загрузка модели является разовой операцией и не характеризует скорость инференса.

## 3. Найденные и исправленные дефекты

### Дефект 1. Захардкоженное имя модели

**В чём заключался дефект**

Имя модели было непосредственно записано в исходном коде. В частности, оно использовалось при загрузке модели в `src/model.py`, а также отдельно выводилось и записывалось в результатах benchmark.

При этом в `params.yaml` предусмотрен параметр:

```yaml
model:
  name: "Qwen/Qwen3-0.6B"
```

Таким образом, в проекте существовали две точки задания модели: конфигурационный файл и исходный код.

**Как проявлялся**

При изменении `model.name` в `params.yaml` программа продолжала использовать модель, имя которой было указано непосредственно в Python-коде. Изменение конфигурации не влияло на фактически загружаемую модель.

Это нарушало основной принцип задания: модель должна выбираться только через `params.yaml`.

**Как исправлен**

В `src/model.py` имя модели теперь берётся из конфигурации:

```python
name = params["model"]["name"]
```

В `generate.py` и `bench.py` имя модели также больше не записано вручную и берётся из:

```python
params["model"]["name"]
```

После исправления смена модели выполняется только изменением `params.yaml`, без изменения исходного кода.

### Дефект 2. Зависимости без зафиксированных версий

**В чём заключался дефект**

В `pyproject.toml` зависимости были указаны без версий:

```toml
"torch",
"transformers",
"accelerate",
"numpy",
"pyyaml",
```

Это означало, что при установке окружения менеджер пакетов мог выбрать актуальные на данный момент версии библиотек.

**Как проявлялся**

Разные пользователи могли получить разные версии одного и того же пакета. Из-за изменений API или поведения библиотек это могло привести к различиям в результатах запуска или к ошибкам при последующей сборке проекта.

Особенно критично это для `torch` и `transformers`, поскольку код напрямую использует их API для загрузки и генерации текста.

**Как исправлен**

В `pyproject.toml` версии основных зависимостей были зафиксированы:

```toml
"torch==2.14.0",
"transformers==5.16.1",
"accelerate==1.14.0",
"numpy==2.5.3",
"pyyaml==6.0.3",
```

Кроме того, зависимости разрешены через `uv`, а файл `uv.lock` хранит конкретное разрешение зависимостей и должен быть включён в репозиторий.

Теперь повторная установка окружения использует зафиксированный набор зависимостей.

### Дефект 3. Неправильный benchmark tokens/sec

**В чём заключался дефект**

В исходном `bench.py` один таймер запускался до загрузки модели:

```python
t0 = time.perf_counter()
tokenizer, model = load_model(params)
```

После этого этим же временем измерялась генерация.

В результате в измерение скорости попадало не только время генерации, но и время загрузки модели.

**Как проявлялся**

Полученное значение `tokens/sec` было искусственно занижено, потому что время загрузки большой языковой модели значительно увеличивало знаменатель.

При этом скорость генерации должна характеризовать именно работу модели после её загрузки и прогрева.

**Как исправлен**

Benchmark разделён на независимые этапы.

Сначала отдельно измеряется время загрузки:

```text
начало → загрузка модели → конец
```

Полученное значение записывается как `load_time_sec`.

После загрузки выполняется прогрев модели. Прогрев не входит в итоговые измерения.

Затем несколько раз отдельно измеряется время генерации:

```text
начало генерации → конец генерации
```

Для каждого запуска вычисляется:

```text
tokens/sec = количество новых токенов / время генерации
```

Итоговое значение рассчитывается как медиана отдельных измерений.

Таким образом, `tokens/sec` теперь отражает непосредственно скорость инференса, а `load_time_sec` показывает отдельную стоимость запуска модели.

### Дефект 4. Отсутствие воспроизводимости генерации

**В чём заключался дефект**

В `params.yaml` был указан seed:

```yaml
seed: 42
```

но он не использовался перед генерацией.

Одновременно при `temperature: 0.7` включался sampling:

```python
do_sample=temperature > 0
```

Поэтому генерация использовала случайность.

В проекте уже существовала функция `set_seed()`, которая фиксировала seed для Python, NumPy и PyTorch, однако до исправления она не вызывалась перед запуском генерации.

**Как проявлялся**

При двух последовательных запусках:

```bash
make generate
make generate
```

модель могла выдавать разные тексты при одинаковом входном промпте и одинаковом конфиге.

Это нарушало требование воспроизводимости эксперимента.

**Как исправлен**

Перед загрузкой и генерацией модели вызывается:

```python
set_seed(params["generate"]["seed"])
```

Функция фиксирует источники случайности:

```python
random.seed(seed)
np.random.seed(seed)
torch.manual_seed(seed)
```

а при наличии CUDA также устанавливается seed для CUDA:

```python
torch.cuda.manual_seed_all(seed)
```

Теперь seed задаётся централизованно через `params.yaml`, а повторные запуски с одинаковой конфигурацией дают воспроизводимый результат.

## 4. Итог

В результате исправлений:

* модель выбирается только через `params.yaml`;
* версии основных зависимостей зафиксированы;
* время загрузки модели измеряется отдельно;
* перед benchmark выполняется прогрев;
* `tokens/sec` рассчитывается только по времени генерации;
* пиковая RSS измеряется отдельно;
* seed берётся из `params.yaml`;
* генерация становится воспроизводимой;
* `uv.lock` используется для фиксации окружения.

Самопроверка выполняется командой:

```bash

```
